# 분산 트랜잭션은 무엇이고, 왜 사용해야할까?

## 한 줄 요약

## 상세 정리

### 1. 개념

- 분산 트랜잭션는 무엇인가?
  - 여러 개의 독립된 저장소나 서비스에 걸쳐 있는 하나의 비즈니스 단위를 마치 **하나의 작업 단위**로 처리하는 기술

- 분산 트랜잭션은 왜 사용해야할까?
  - 여러 개의 독립된 서비스로 분리를 했는데 하나의 비즈니스 단위를 하나의 작업 단위로 처리를 해야하기 때문에 사용해야함.
     

### 2. 특징

#### 2PC 패턴

오케스트레이터가 각 서비스를 제어하는 방식으로 각 서비스가 ready 상태가 될 때까지 대기하여. 모든 서비스가 ready 상태가 되어야지 commit을 수행한다.
  - 오케스트레이터가 SPOF (Single Point Of Failure)가 된다.
  - 모든 서비스가 reeady 상태가 될 때까지 기다려야하므로 처리량이 낮다.
  - 서비스가 늘어날 경우 대처하기가 함들다. (확장성이 낮다)

위와 같은 단점들이 있기 때문에 성능과 가용성 확보를 위해 SAGA 패턴을 사용한다.

#### SAGA 패턴

분산 시스템에서 각 서비스의 로컬 트랜잭션을 순차적으로 실행하고, 중간에 실패가 발생하면 이미 완료된 작업들을 '보상 트랜잭션'을 통해
논리적으로 되돌려 시스템 전체의 최종적 일관성을 유지하는 데이터 관리 패턴

  - 로컬 트랜잭션 : 각 서비스 내부에서 독립적으로 실행되며 ACID가 보장되는 단위 작업
  - 보상 트랜잭션 : 작업 실패 시, 이미 완료된 로컬 트랜잭션의 결과를 논리적으로 취소하는 별도의 비즈니스 로직
  - 최종적 일관성 : 데이터가 일시적으로 불일치할 수 있으나, 결국에는 일관된 상태에 도달함을 보장

###  SAGA 패턴의 장단점

  - 장점
    - 각 서비스가 로컬 트랜잭션 단위로 동작하므로 2PC 방식보다 성능과 확장성 측면에서 유리하다.
    - 중앙 조정자에 대한 의존도를 낮출 수 있어 가용성 측면에서 유리하다.
    - 실패 시 보상 트랜잭션을 통해 비즈니스 요구사항에 맞는 유연한 복구가 가능하다.
  - 단점
    - 서비스 간의 트랜잭션 흐름과 의존 관계가 복잡해진다.
    - 보상 트랜잭션을 직접 설계하고 구현해야 하므로 개발 난도가 높다.
    - 최종적 일관성을 기반으로 하므로 일시적인 데이터 불일치가 발생할 수 있다.

### 5. 실무에서 볼 포인트

- 각 로컬 트랜잭션에 대응하는 보상 트랜잭션을 비즈니스 관점에서 명확히 설계해야 하며, 일반적으로 보상은 수행의 역순으로 처리한다.
- 즉시 일관성이 아닌 최종적 일관성을 수용해야 하므로, 일시적인 데이터 불일치 상황을 고려해야 한다.
- 메시지 재전송, 재시도, 중복 소비에 대비해 로컬 트랜잭션과 보상 트랜잭션 모두 멱등하게 구현해야 한다.
- 실패 시 재시도 정책, 보상 수행 조건, 장애 복구 전략을 사전에 정의해야 한다.
- Saga가 현재 어느 단계까지 진행됐는지 추적할 수 있도록 상태 관리와 모니터링 체계를 갖춰야 한다.
- 서비스 간 이벤트와 책임 경계를 명확히 설계하여 복잡한 의존 관계를 줄여야 한다.
